# AI CFO — AWS Deployment Guide (EC2 + Docker Compose)

This guide deploys the **full stack** — frontend (React/Vite), FastAPI backend
and MongoDB — to AWS on a **single EC2 instance running Docker Compose**, with
Caddy as the edge server (static SPA + `/api` reverse proxy + automatic HTTPS).

- **Infrastructure:** Terraform (`infra/terraform/`)
- **App stack:** `docker-compose.prod.yml`
- **Bootstrap / ops scripts:** `deploy/`
- **CI/CD:** `.github/workflows/deploy.yml`

---
## Architecture

```
                        Internet
                           │ (80/443)
                           ▼
                 ┌──────────────────────┐
                 │  EC2 (t3.small)      │  Elastic IP
                 │  ┌────────────────┐  │
                 │  │  Caddy         │  │  :80/:443  → SPA + HTTPS
                 │  │  (frontend)    │  │              (Let's Encrypt)
                 │  ├────────────────┤  │
                 │  │  /api, /health │──┼──► FastAPI (:8000, internal)
                 │  ├────────────────┤  │
                 │  │  MongoDB 7     │  │  :27017 (internal only)
                 │  └────────────────┘  │
                 │  EBS data disk:      │
                 │  /var/lib/docker     │  (DB + certs survive restarts)
                 └──────────────────────┘
```

Why this shape:

- **One server, one bill** — good fit for an MSME app at low traffic; free
  tier can cover the first 12 months (see costs below).
- **Caddy in front** serves the built SPA *and* proxies `/api` + `/health` to
  FastAPI, so the browser talks to a single origin (no CORS friction, no
  per-request public API endpoint needed).
- **Dedicated EBS data volume** keeps MongoDB data safe if the instance is
  ever replaced/upgraded.
- **Secrets never touch Git** — generated by Terraform into SSM Parameter
  Store (SecureString); the host `.env` is mode 600 and re-hydrated on boot.

## What gets deployed

| Component | How |
| --- | --- |
| Frontend | `Dockerfile` (multi-stage: `node:22-alpine` build → `caddy:2-alpine`) |
| Backend | `backend/Dockerfile` (FastAPI on `uvicorn`, non-root) |
| Database | `mongo:7.0`, auth enabled, app user created by `deploy/mongo-init.js` |
| Edge | `deploy/Caddyfile` — SPA fallback, gzip, security headers, `/api` proxy |
| Backups | `deploy/backup.sh` — nightly `mongodump` (local 7 days, optional S3) |
| Re-deploys | `deploy/update.sh` — git pull → compose rebuild → health check |

## Estimated monthly cost (us-east-1 / ap-south-1, ~rough)

| Item | Cost |
| --- | --- |
| EC2 t3.small (Linux, on-demand) | ~$15–16/mo |
| EBS gp3 20 GB root + 30 GB data | ~$4/mo |
| Elastic IP (attached) | $0 |
| CloudWatch logs (optional) | ~$1/mo |
| S3 backups (if enabled, small) | pennies |
| **Total** | **~$20–25/mo** (with `t3.micro` you can stay on the AWS **free tier** for 12 months: 750 instance-hours/month is enough for a small app — the stack runs fine at low load; just relax the CPU/RAM limits) |

## Prerequisites

- AWS account + IAM user with `AdministratorAccess` (or at least EC2, VPC,
  IAM, SSM, SSM-Parameter-Store, Route 53, ACM, S3 permissions used here)
- AWS CLI configured: `aws sts get-caller-identity` succeeds
- Terraform ≥ 1.5: https://developer.hashicorp.com/terraform/downloads
- Node 20+ and Python 3.11+ only if you want to run the build/tests locally
- A **public GitHub repo** (this repo is public) so the EC2 bootstrap can
  clone it without credentials. For a private repo, either make it public or
  add a fine-grained read PAT as `GITHUB_TOKEN` on the host and adapt
  `deploy/bootstrap.sh`.
- Optional: a domain whose DNS is hosted in **Route 53** (for HTTPS)

# Option A — Fully automated (recommended)

## 1. Configure

```bash
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars`:

```hcl
aws_region        = "ap-south-1"        # Mumbai — near India
instance_type     = "t3.small"          # t3.micro if using free tier
data_volume_size_gb = 30

# optional, for HTTPS + pretty URL:
domain_name       = "app.example.com"
route53_zone_name = "example.com"

# optional, off-site database backups:
backup_bucket_name = "aicfo-prod-db-backups"

# optional, AI provider keys (prefer env vars, NOT this file):
# openai_api_key = "..."   → use: TF_VAR_openai_api_key=... terraform apply
```

## 2. Deploy

```bash
terraform init
terraform plan        # review what will be created
terraform apply       # 5–10 min: instance + Docker install + npm build + pulls
```

## 3. Verify

```bash
terraform output public_url    # e.g. http://13.x.x.x  or https://app.example.com
curl $(terraform output -raw public_ip)/health
# → {"status":"ok","service":"AI CFO ...","mongodb":"up", ...}

terraform output ssm_session_command
# shell on the server without SSH:
aws ssm start-session --target <instance-id> --region ap-south-1
```

Open the URL, register an account, and try the dashboard. On the server:

```bash
sudo docker compose -f /home/ubuntu/aicfo/docker-compose.prod.yml ps
sudo docker compose -f /home/ubuntu/aicfo/docker-compose.prod.yml logs -f backend
```

## What `terraform apply` does under the hood

1. Creates VPC, public subnet, IGW, security group (80/443 open; SSH closed
   by default), IAM role (SSM + secret reader), EC2 instance + EIP + encrypted
   root + **30 GB encrypted data disk**, and SSM parameters:
   `/aicfo/prod/jwt_secret`, `/mongo_root_password`, `/mongo_app_password`.
2. The instance's cloud-init runs `deploy/bootstrap.sh`:
   - format + mount data disk at `/var/lib/docker`
   - `apt install docker.io docker-compose-v2 awscli` + SSM agent
   - read secrets from SSM → write `.env` (600)
   - `git clone --branch main` the repo
   - `docker compose -f docker-compose.prod.yml up -d --build`
   - install nightly backup cron
3. Optional: ACM certificate + Route 53 A record for your domain; Caddy then
   obtains a Let's Encrypt certificate automatically on first request.

## Custom domain / HTTPS

Just set `domain_name` (+ `route53_zone_name`) in `terraform.tfvars` before
applying (or re-apply afterwards — changing `domain_name` re-bootstraps the
instance; the data disk keeps MongoDB).

- Terraform creates the ACM cert (DNS validation) and A records.
- Caddy server block switches from `:80` (plain HTTP) to `app.example.com`
  (automatic HTTPS) because `DOMAIN` is written into `.env` at bootstrap time.
- Need a certificate without Route 53? Leave `domain_name` unset and manage
  the cert in Caddy manually (see `deploy/Caddyfile`).

# Option B — Manual (no Terraform)

Good for learning what's happening, or if you want a different AWS setup
(Lightsail, another region, etc.).

1. **Launch an instance** — Ubuntu 24.04 LTS, `t3.small`/`t3.micro`, 20+ GB
   disk, assign a public IP, security group allowing 80 and 443 from
   `0.0.0.0/0` (22 only from your IP if you want SSH).
2. **SSH in** (`ubuntu@<public-ip>`), then:

```bash
sudo apt update && sudo apt install -y docker.io docker-compose-v2 git
sudo usermod -aG docker $USER && newgrp docker   # or use sudo docker ...

git clone https://github.com/sjg-2903/aicfo.git
cd aicfo
cp deploy/.env.production.example .env
nano .env        # set MONGO_* passwords, JWT_SECRET, DOMAIN/CORS_ORIGINS

docker compose -f docker-compose.prod.yml up -d --build
curl http://localhost/health
```

3. **Upgrades:**

```bash
cd ~/aicfo
git pull --ff-only
docker compose -f docker-compose.prod.yml up -d --build
```

4. **Backups** (optional):

```bash
# cron entry for root (or ubuntu) — runs nightly at 02:20:
20 2 * * * /home/ubuntu/aicfo/deploy/backup.sh >> /home/ubuntu/aicfo-backup.log 2>&1
```

# CI/CD — deploy on every push to main

> The workflow lives at `ci/deploy.yml` instead of `.github/workflows/`
> because the repository's GitHub App token cannot push workflow files
> without the **Workflows** permission. Activate it once with:

```bash
mkdir -p .github/workflows
cp ci/deploy.yml .github/workflows/deploy.yml
# commit + push (or ask the repo owner to grant the app 'Workflows: read and write')
```

`ci/deploy.yml`:

1. **verify job** — `npm ci && npm run build` (frontend) and
   `pytest backend/tests` (backend, in-memory MongoDB — no external services).
2. **deploy job** (main only) — asks the EC2 host via **SSM**
   (`AWS-RunShellScript` → `sudo -u ubuntu bash /home/ubuntu/aicfo/deploy/update.sh`),
   then polls the command and curls `/health`.

## GitHub Actions secrets

| Secret | Value |
| --- | --- |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | IAM credentials (see policy below) |
| `AWS_REGION` | e.g. `ap-south-1` |
| `EC2_INSTANCE_ID` | `terraform output instance_id` |

Minimal IAM policy for the deploy user:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["ssm:SendCommand", "ssm:GetCommandInvocation"],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": "ec2:DescribeInstances",
      "Resource": "*"
    }
  ]
}
```

The EC2 instance needs the **SSM agent** — installed by the Terraform
bootstrap — and the `AmazonSSMManagedInstanceCore` policy (also attached by
Terraform). Give it ~2 minutes after launch before the first CI deploy.

**Rollback:** `git checkout <previous-tag> && deploy/update.sh`, or re-run
the previous workflow with `workflow_dispatch`.

# Backups & restore

Bootstrap installs a nightly cron (02:15 server time) running
`deploy/backup.sh`:

- `mongodump --archive --gzip` → `/home/ubuntu/aicfo-backups/aicfo-<ts>.archive.gz`
- local retention: 7 days
- if `backup_bucket_name` was set in Terraform:
  also uploads to `s3://<bucket>/aicfo/<ts>.archive.gz`

Restore:

```bash
cd /home/ubuntu/aicfo
docker compose exec -T mongo sh -c '
  mongorestore --archive --gzip --drop \
    --username "$MONGO_INITDB_ROOT_USERNAME" \
    --password "$MONGO_INITDB_ROOT_PASSWORD" \
    --authenticationDatabase admin
' < /home/ubuntu/aicfo-backups/aicfo-2026-08-22_021500.archive.gz
```

Verify the backup bucket periodically — `aws s3 ls s3://<bucket>/aicfo/ --recursive`.

CloudWatch Synthetics canary).

# Security checklist

- [x] **No inbound SSH** by default (SSM Session Manager instead); if you
      add `key_name`, restrict `allowed_ssh_cidrs`
- [x] MongoDB is not published to the host — only Caddy's 80/443 are
- [x] Mongo auth enabled; backend uses a least-privilege `aicfo_app` user
- [x] Secrets in SSM SecureString, `.env` mode 600, never in Git
- [x] Encrypted root + data EBS volumes, IMDSv2 required
- [x] HTTPS via Let's Encrypt when a domain is configured
- [x] Security headers set by Caddy (HSTS, nosniff, frame-options, ...)
- [x] Nightly encrypted-to-S3 database backups (if enabled)
- [ ] Keep `terraform.tfstate` private (move to S3 backend + DynamoDB lock
      for teams — see `infra/terraform/versions.tf`)
- [ ] Set strong `JWT_SECRET` if you deploy manually
- [ ] Review IAM — no `*` except the outbound egress the app requires

# Troubleshooting

| Symptom | Fix |
| --- | --- |
| `curl http://<ip>/health` times out | Instance still bootstrapping; watch `/var/log/aicfo-bootstrap.log`. SG must allow 80. |
| Browser shows `421 Misdirected Request` on the IP | `DOMAIN` is set — use `https://<domain>` instead (the IP site is disabled). Unset `DOMAIN` to serve HTTP on the IP. |
| 404 after refreshing `/dashboard` | SPA fallback should handle it; check Caddy `try_files {path} /index.html` (it is configured) and that you're on the new frontend image (`docker compose pull/build`). |
| `/api` calls fail with 502 | Backend unhealthy: `docker compose -f ... logs backend`; Mongo auth error is usually a bad password in `.env`/SSM. |
| Mongo healthcheck never green | Re-init: data volume was initialized with different credentials (init scripts run only on an empty data dir). Fix `.env`, then reset the volume **only if data loss is acceptable**, or create the app user manually with `docker compose exec mongo mongosh -u root -p <pwd> --authenticationDatabase admin`. |
| SSM Session Manager / Actions deploy fails | Agent not ready (wait ~2 min) or instance profile missing `AmazonSSMManagedInstanceCore`; check `systemctl status snap.amazon-ssm-agent.ssm-agent`. |
| Let's Encrypt fails | DNS A record must point at the EIP and propagate; ACM cert must be validated (Terraform does this). Check `docker compose logs caddy`. |
| `terraform apply` resets the server | `user_data_replace_on_change` re-bootstraps when inputs change. Data survives (separate EBS volume) but expect ~5 min downtime. |
| Memory pressure (OOM kills) | t3.micro/t3.small can be tight: `docker compose -f ... logs backend`, set `--memory` limits in compose, or move to t3.medium. |
| Mongo/Caddy volumes grew | Nightly `backup.sh` retention handles backups; `docker system df` to find bloat; prune images per `deploy/update.sh`. |
| Cost creep | t3 instances accrue while running — stop/release when not needed (data disk keeps data), monitor via AWS Cost Explorer. |

```bash
cd infra/terraform
```

> lost.** Export one final backup first (`deploy/backup.sh`, or `aws s3
> sync` the bucket) if you might need it. If you want the S3 bucket to
> survive, manage it outside this config.

# Appendix — Frontend-only static hosting (S3 + CloudFront)

If you only want the React app on AWS (API hosted elsewhere), the same
`npm run build` output can be served from S3 behind CloudFront. Summary:

```bash
npm run build
aws s3 mb s3://aicfo-frontend-prod --region us-east-1
# block all public access; enable versioning
aws s3 sync dist/ s3://aicfo-frontend-prod --delete \
  --cache-control "max-age=31536000,immutable" --exclude "index.html"
aws s3 cp dist/index.html s3://aicfo-frontend-prod/index.html \
  --cache-control "max-age=0,must-revalidate" --content-type "text/html"
```

CloudFront distribution:

- Origin: the S3 bucket, **Origin Access Control (OAC)** (not public bucket)
- Bucket policy: allow `cloudfront.amazonaws.com` `s3:GetObject` on the OAC
  (`AWS:SourceArn` = distribution ARN)
- Default root object `index.html`, compress objects, redirect HTTP→HTTPS
- **Error response: 404 → `/index.html` with 200** (React Router client-side
  routes)
- The SPA calls `<api-host>/api` — set `VITE_API_BASE_URL` at build time
  (`npm run build` with the env var) and ensure the backend's CORS allows
  your CloudFront domain.
